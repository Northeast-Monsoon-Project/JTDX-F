# JTDX-F V3.3.0

JTDX-F 是 Fluxmancer 基于 JTDX **2.2.159** 创建的独立分支。保留上游作者署名和 GNU GPLv3 许可。新的猫巫师 Logo 由团队提供，用于主程序图标、Windows 安装程序及“关于”窗口。

## Windows 安装

使用 `JTDX-F-V3.3.0-Windows-x64-Setup.exe`，目标为 Windows 10/11 64 位。默认安装到当前用户目录，无需安装 Wine、Qt 或编译器。安装程序包含所需运行库；安装包未进行商业代码签名。

安装后从开始菜单启动 JTDX-F。这个分支采用独立应用名称和设置目录，不覆盖原 JTDX 的设置和通联日志。首次使用请在设置中确认呼号、网格、声卡、CAT/PTT、频率、日志选项和系统时间。在电台资料中新增呼号后，可把旧 ADIF 拖入主窗口导入。文件菜单可打开当前呼号的日志目录。

OmniRig 使用原来的独立 COM 服务，选择 OmniRig 的用户仍需在 Windows 安装/注册 OmniRig。使用 Hamlib CAT 的用户不需要 OmniRig。

同一分支的新版安装到已有 JTDX-F 目录并覆盖程序；日志和设置位于独立的用户数据目录，不随安装覆盖。已有较新版本时，安装器会询问是否降级，默认选“否”；静默安装不会自动同意降级。JTDX、JTDX-FM 等其他分支可以共存。

## 托管模式

主菜单“托管模式”可选 DXCC猎人、QSO爱好者或关闭；每次启动默认关闭。设置页位于过滤之后、计划程序之前，可配置目标、是否回答已通联电台及 0～99 次呼叫上限。仍需人工启用发射；空闲监听，仅在符合目标、收到来电或周期 CQ 到期时发送。详细优先级、重试和强制三轮 CQ 规则见 [托管模式说明](托管模式_zh.md)。

显示通知中的“曾经通联（隐藏不显示）”默认关闭。勾选后仍保留当前 QSO 和发给自己的消息。

## 呼号与日志

在“设置 → 常规 → 电台资料”选择当前呼号，旁边的“呼号管理”可以新增、修改和删除资料。网格、IARU 分区、第 2 类呼号选项均在管理窗口中。呼号统一转为大写，不能重复；`N0CALL`、`N0CALL/P`、`N0CALL/QRP` 是不同资料。管理窗口及设置窗口均点确定后保存。启用发射的整个会话内（含收听周期）和调谐期间禁止切换。

每个呼号使用数据目录下的独立子目录；斜杠变为下划线，例如 `N0CALL_QRP/`。移除或改名呼号不会删除旧目录，重新建立原呼号会继续读取它。删除日志需要操作员通过文件管理器手动完成。

通联按 UTC 开始日期分季度保存，如 `N0CALL2026S3.adi`。查重会读取当前呼号目录中全部 ADIF 历史，不限于本季度。把 `.adi`、`.adif` 或旧 `wsjtx.log` 拖入主窗口即可后台转换；原始文件备份到该呼号目录的 `old/`。外部拖入的源文件保留不动，直接放进呼号目录的旧格式文件在转换和备份成功后移入 `old/`。重复导入按通联身份去重；不完整或无法解析的文件不会删除。包含 `STATION_CALLSIGN` 的记录归入相应呼号目录；缺少该字段的记录归入当前呼号。工作区提供的私有日志不随程序和源码包发布。

## 发射与默认选项

启动软件时发射保持停止。只有在界面上人工点击“启用发射”（或其键盘快捷键）才能建立发射会话；自动应答、UDP、MCP、设置恢复和延时回调不能开启一个已停止的会话。点击“停止”立即撤销授权、取消待执行重启任务并释放 PTT。调谐需明确的人工操作，结束后不会恢复先前通联。

新配置默认启用解码周期间隔行、Tx/Rx 异频和自动记录通联日志。V3.1.1 已修正 V3.1.0 仍默认锁定 Tx=Rx 的问题：首次升级会切换为 Tx/Rx 异频，之后继续记住操作员的手动选择。其他已保存的用户选项继续保留。已移除“73 后用 CW 发呼号”和“发射 CW 信息时间间隔”，旧配置中的这两项均不会重新生效。

## NTP 校时

“设置 → 常规 → NTP 校时”默认不勾选，内容灰显，此时本功能不查询服务器、不修改系统时间。勾选后会立即申请校时权限；选择服务器并点“确定”后开始校时，之后默认每 15 分钟检查一次。网络错误时每 1 分钟重试，结果显示在同一栏目。设置保持开启时，重新启动软件会再次申请本次运行所需的权限。

服务器在同一个列表中，亚洲在最前，随后为欧洲、非洲、北美、南美、大洋洲及全球服务，共 50 项；不使用“国内／国外”分类。选择“其他”后，右侧出现自定义域名或 IPv4/IPv6 地址输入框，不填写 `https://`、路径或端口。新西兰 MSL 的预设注明“限新西兰网络”，这是该服务商的访问限制。每家最多 2 个公开地址；校时间隔可选 1、5、10、15、30 分钟，1、3、6、9、12 小时，默认 15 分钟。完整名单及来源见 [NTP 校时说明](NTP校时_zh.md)。

Windows 使用 UAC，Linux 使用 polkit/pkexec 授权一个单独的校时辅助进程。权限不足或取消授权时继续使用系统时间，不会假装校时成功；可取消勾选再勾选以重新申请。关闭选项或退出软件后停止本软件的校时进程。更换 NTP 设置后需要点“确定”；点“取消”恢复原设置。

**NTP 返回 UTC，校时调整的是系统时钟，不修改用户时区。** Windows/Linux 桌面仍显示所选时区的本地时间；JTDX-F 时隙、UTC 时间显示与通联日志继续使用 UTC。例如 UTC 00:00 在 UTC+8 桌面显示 08:00，两个值表示同一时刻，不会再加一次时差。发射/PTT 期间暂缓校时，避免在发射中途调整时钟。

## 日志处理提示

切换呼号并确认设置、转换旧日志时显示“系统处理中，请稍候…”。转换完成后还会等待历史日志载入，全部完成才关闭提示；失败也会关闭，并在状态栏说明原因。文件读取、解析和转换在后台进行，界面仍能刷新进度。若当时已启用发射，弹窗保留“停止发射”按钮。正常日志更新不会因为内部锁文件变化反复重载。

## SuperFox

“DX 远征 → SuperFox 解码（SuperHound 模式）”启用接收支持，同时进入 Hound 模式，Rx 初始设为 750 Hz；可在同一菜单设置 5～200 Hz 的频率容差，默认 75 Hz。切换模式会停止发射，需人工重新启用。SuperHound 使用普通 FT8 回复，关闭旧 Hound 的自动发射频率下跳；本版本不发送 SuperFox 波形。

SuperFox 解出的 RR73、报告和 CQ 进入正常的显示、通联和 MCP 解码流程。该版本没有实现远征身份 OTP 在线认证，收到签名不表示身份已经验证；MCP 签名事件明确返回 `verified: false`。接收代码来源和独立测量表的记录见 `lib/superfox/PROVENANCE.txt`。音频回归使用本地生成的模拟信号，不涉及射频发射。操作时按远征公告选择频率，参考 [上游 SuperFox 指南](https://wsjt.sourceforge.io/SuperFox_User_Guide.pdf)。

## 连续 FT8 通联

- 开启 AutoSeq，选择自动程序的首段/中段/末段候选选择方式，关闭“单次通联”。
- 设置中的发射监管计时器可填 0～999 分钟。0 表示不限时；正数从开启发射开始累计，跨通联保持，不被鼠标、解码和记录日志重置。
- 通联完成后优先应答符合现有筛选条件的呼叫；允许搜索 CQ/呼叫已通联电台时，也可直接开始下一轮应答。无候选才 CQ。
- 发射时隙根据新目标调整，完成消息的发射不会因选择下一位而提前打断。
- 开启“单次通联”仍会在本次结束时停止；计时到期、手动停止、设备错误等停止条件仍然有效。再次手动开启发射才开始新计时会话。

QSO 完成与日志记录是两个概念。日志自动记录仍由原有自动日志/提示设置控制；本分支不会未经交换就伪造已完成通联。

## MCP

详见 [MCP 中文指南](MCP_zh.md)。服务默认为关闭，只接受本机令牌认证的连接。HTTP 客户端直接连接，stdio 客户端使用附带的 Python 桥接脚本。

## 稳定性与故障排查

本版本修复了经源码审查确认的若干缺陷，并加入通联、音频读取、网络回复、MCP 和解码故障恢复测试。详见 [审查记录](审查记录_zh.md)。这些修复不等于所有电台、声卡驱动和 Windows 环境都已实测无故障。

遇到异常时请记录：版本、操作系统、模式、声卡型号、CAT/PTT 类型、是否连接 OmniRig/HRD/TCI、异常时刻及复现步骤。解码进程异常会停止发射并保留主界面，错误写入当前呼号日志目录的 `decoder-errors.log`；重启解码器后需要点击“监听”恢复接收。

源码、许可和构建说明随发行资料提供；修改源文件的工作差异可与仓库导入的原版基线比较。

详细服务器清单、UTC 处理和权限说明见 [NTP 校时说明](NTP校时_zh.md)。
